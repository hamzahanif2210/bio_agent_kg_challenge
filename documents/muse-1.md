Topic 1 — LLM agents building biomedical KGs ([me] = I opened it; [sub] = research subagent opened it)

[A1] ChronoMedKG: A Temporally-Grounded Biomedical Knowledge Graph and Benchmark for Clinical Reasoning — Ahmed, Firoozbakht, Galke Poech et al.; arXiv 2605.22734, May 2026. https://arxiv.org/abs/2605.22734 [me]. Four sequential agents (MONDO/OMIM/HPO profiler → NCBI E-utilities harvester → 2–3 LLMs in parallel keeping ≥2-model consensus triples → PrimeKG-schema quality controller); every triple carries PMID + verbatim quote + six-signal credibility score. Key result: 460,497 validated triples from 13M raw extractions (3.53% retention) over 13,431 diseases; 92.7% agreement vs Orphadata. Code: GitLab (link in paper), data DOI 10.5281/zenodo.19697542, license not stated. Use it: copy consensus-filter + PMID/quote provenance into Clean/Explainability; prompts in Appendix G (2–4d). Caveat: frontier-model calls at their scale are expensive — apply consensus only to at-risk edges.
[A2] Clinical Knowledge Graph Construction and Evaluation with Multi-LLMs via Retrieval-Augmented Generation — Das, Atmakuri, Ho et al.; arXiv 2601.01844, Jan 2026. http://arxiv.org/abs/2601.01844 [sub]. Five stages: FHIR-guided extraction (Gemini 2.0 Flash) → ontology mapping (SNOMED CT/LOINC/RxNorm/GO/ICD) → GPT-4o relation refinement → RDF/OWL encoding → composite trust function with adversarial contradiction-testing; continuous self-supervised refinement ≈ your Maintain step. Key result: not reported numerically. No code found. Use it: staged model specialization as blueprint for your Ingest→Filter→Clean agents (1–2d). Caveat: 40 clinical reports only; proprietary three-model cost — substitute Haiku-class for cheap stages.
[A3] Scientific Agent Skills (K-Dense / kim-autorobotics) — paper arXiv 2609.00065, Sep 2026; repo created 2026-09-17. https://github.com/kim-autorobotics/claude_scientifi_skills [me]. 166 agent skills for Claude Code-class agents: unified lookup over 78 scientific DBs (PubChem, ChEMBL, UniProt, COSMIC, ClinicalTrials.gov…), BioPython/Entrez, gget, a PrimeKG skill, and an NCATS ARAX skill for bounded Biolink-constrained KG queries with provenance. MIT license. Use it: steal the ARAX + DB-lookup skill definitions as tool-use templates for your Claude Ingest agents (4–8h). Caveat: 3 stars, 3 weeks old — verify each skill's endpoints and ARAX rate limits.
[A4] Large language models for intelligent RDF knowledge graph construction: results from medical ontology mapping — Mavridis, Tegos, Anastasiou et al.; Frontiers in AI, Apr 2025 (PMID 40352975). https://pubmed.ncbi.nlm.nih.gov/40352975/ [sub]. Six systems map 108 medical terms to SNOMED CT using BioBERT embeddings + ChromaDB retrieval feeding an LLM verifier. Key result: GPT-4o precision 93.75%, F1 96.26% — best of six. No code reported. Use it: "embedding retrieval first, LLM verify second" as your Biolink mapping step (1–2d). Caveat: 108 terms, SNOMED-only; small open models lag.
[A5] Data Overdose? Time for a Quadruple Shot — Elliott, Levitt, Nixon et al.; SAICSIT 2025 / arXiv 2508.03438, Aug 2025. https://arxiv.org/abs/2508.03438 [sub]. LLM agents chunk 44 PubMed abstracts into proposition sentences (semantic chunking + coreference), extract triples, enhance into "quadruples" (triple + context variable). Key result: 0.874 mean cosine similarity between regenerated sentences and original propositions. No code. Use it: proposition-level chunking + context variable per edge for provenance (1–2d). Caveat: pilot-scale; cosine similarity is a weak correctness proxy; map the free-text context to Biolink qualifiers or it hurts Standards.

Subgraph retrieval as Prize-Collecting Steiner Tree optimization + GNN+LLM reader (soft-prompt fine-tuned); hallucinations grounded in retrieved graph evidence. [A7] BiomedQA (samyama-ai) — benchmark, repo created 2026-03-18; used in arXiv:2603.15080, GRADES-NDA/aiDM 2026. https://github.com/samyama-ai/biomedqa [me]. 40 pharmacology questions over 3 biomedical KGs (7.9M nodes, 28M edges): pre-authored MCP tool templates vs GPT-4o text-to-Cypher vs GPT-4o standalone. Key result: MCP tools 39/40 (98%) vs text-to-Cypher 34/40 (85%) vs standalone 30/40 (75%); MCP had zero schema errors. Apache-2.0. Use it: don't build raw text-to-Cypher — ship 30–50 curated parameterized query tools for Filter (~1d). [A8] CypherTurn — Zhang, Zhu, Yang et al.; arXiv 2609.36987, Sep 2026. https://arxiv.org/abs/2609.36987 [me]. First multi-turn text-to-Cypher benchmark: 721 sessions / 5,927 turns / 7 KGs. Key result: best model 64.7% execution accuracy; session-level correctness <5%; "autonomy divergence" — leaderboard reorders under autonomous operation. Code in paper. Use it: stress-test for your conversational NL interface; require session-level passes; design error recovery (1–2d). Caveat: synthetic non-biomedical graphs; very fresh preprint.
[A9] Combining LLMs and Knowledge Graphs to Reduce Hallucinations in Biomedical QA — Pusch & Conrad; BioMedInformatics 2025, 5, 70. https://www.mdpi.com/2673-7426/5/4/70 [me]. LangChain text-to-Cypher over a PrimeKG subset with a three-part query-checker (syntax / node-type / relation-direction) validating queries pre-execution; 50 tailored questions. Key result: GPT-4 Turbo 45/50; the checker took GPT-4o from 1→40 correct and GPT-5 from 1→42. Code: https://git.zib.de/lpusch/cyphergenkg-gui (CC open access). Use it: schema-aware query checker as mandatory post-processing for any generated query (1–2d). Caveat: exact-match Cypher eval is brittle; open models lag (Llama3.3:70b 0.62).
[A10] Injecting Structured Biomedical Knowledge into LMs: Continual Pretraining vs. GraphRAG — Klila et al.; arXiv 2604.16422, Apr 2026. https://arxiv.org/abs/2604.16422 [sub]. 3.4M-concept / 34.2M-relation UMLS KG; compares continual pretraining vs inference-time GraphRAG. Key result: GraphRAG on LLaMA 3-8B gives +3 pts PubMedQA, +5 BioASQ with no retraining (CC-BY 4.0). Use it: settle for inference-time GraphRAG over your KG — small-GPU friendly (2–3d). Caveat: verify their released UMLS graph's license before ingesting; UMLS enrichment near test edges = leakage risk.

Topic 2 — Pruning / cleaning

[B1] GraphJudge: Can LLMs be Good Graph Judge for Knowledge Graph Construction? — Huang, Chen, Sheng et al.; arXiv 2411.17388 (EMNLP 2025 main). https://arxiv.org/abs/2411.17388 [me]. Entity-centric text denoising → fine-tuned Llama-2 "graph judge" (KASFT) → triple filtering. Key result: judge >90% accuracy on graph-judgement tasks; SOTA on two general + one domain (SciERC) datasets. Code: https://github.com/hhy-huang/GraphJudge, MIT; LoRA weights on HF. Use it: fine-tune an open LLM as yes/no judge over your (triple, source-abstract) pairs; batch-filter the edge table (3–5d). Caveat: needs labeled correct/incorrect triples — bootstrap from Pharos edges vs random corruptions.
[B2] Refining Noisy Knowledge Graph with Large Language Models (LLM_sim) — Dong Na, Kertkeidkachorn, Liu et al.; ACL 2025 GenAIK workshop. https://preview.aclanthology.org/override-month/2025.genaik-1.9.pdf [sub]. Llama-3 yes/no per-triple noise detection with fuzzy-search context over structurally similar triples; refinement via 5 candidates. Key result: F1 0.951 noise detection on WN18RR at 10% noise; KGC MRR 0.423→0.434; 89% human-rated refinement. No code released. Use it: replicate as second-stage filter for low-confidence edges — matches your planned "confidence reweighting from literature or a GNN" (2–3d). Caveat: per-triple 8B calls are GPU-expensive — gate to suspect edges; evaluated on general KGs, not biomedical.
[B3] UnKGCP: Certainty in Uncertainty — Zhu, Wu, Wang et al.; arXiv 2510.24754, Oct 2025 (EMNLP 2025). https://arxiv.org/abs/2510.24754 [sub]. Conformal prediction for uncertain KG embeddings — prediction intervals with statistical coverage guarantees instead of point scores. Key result: not reported numerically. Code released per abstract; preprint carries CC BY-NC-SA 4.0. Use it: wrap your PyG link-predictor scores with conformal intervals from a held-out calibration set → principled per-edge pruning confidence (1–2d). Caveat: NC license; calibration set must be strictly separate from test edges.
[B4] GroundLens (project, no paper) — groundlens-dev; GitHub created May 2026. https://github.com/groundlens-dev/groundlens [sub]. Execution-verification runtime: deterministic verifiers (numeric, lexical, semantic, NLI entailment/contradiction) check agent answers against sources; PASS/REVIEW/FAIL + hash-chained evidence records. Apache-2.0; pip install groundlens. Use it: NLI verifier per extracted triple vs its source sentence → entailment label as per-edge provenance evidence (1–2d). Caveat: 7 stars, not biomedical-tuned; may over-flag paraphrase-heavy text.

Topic 6 — Keeping the KG up to date

[B5] Zep / Graphiti: A Temporal Knowledge Graph Architecture for Agent Memory — Rasmussen, Paliychuk, Beauvais et al.; arXiv 2501.13956, Jan 2025. https://arxiv.org/abs/2501.13956 [me]. Bi-temporal edges (valid/invalid + created/expired timestamps); contradictions trigger automatic invalidation, never deletion; episodes = provenance. Key result: DMR 94.8% vs MemGPT 93.4%; LongMemEval +18.5% accuracy, −90% latency. Code: https://github.com/getzep/graphiti, Apache-2.0, ~31.6k stars. Use it: adopt the invalidation pattern in your Parquet edge tables (valid_from/valid_to + created/expired columns) plus episode-level provenance; skip Neo4j (3–4d). Caveat: built for agent memory; write path needs LLM calls per fact.
[B6] ATOM: AdapTive and OptiMized dynamic temporal KG construction using LLMs — Lairgi, Moncla, Benabdeslem et al.; arXiv 2510.22590, Oct 2025. https://arxiv.org/abs/2510.22590 [sub]. Few-shot continuous update: documents → atomic facts → small temporal KGs merged via G^t = G^{t-1} ⊕ snapshot, no rebuild. Key result: ~18% higher exhaustivity, ~17% stability, >90% latency reduction vs baselines. Code at https://github.com/AuvaLab/itext2kg per paper — not opened, license unconfirmed. Use it: per-PubMed-batch extract + parallel merge with observation/validity timestamps (3–5d). Caveat: code unverified; predicates need Biolink mapping.
[B7] iKraph/BioKG — Zhang, Sui, Pan et al.; Nature Machine Intelligence 2025 (DOI 10.1038/s42256-025-01014-w). https://pmc.ncbi.nlm.nih.gov/articles/PMC10760044/ [sub]. The pipeline that won 1st place in the NIH LitCoin NLP challenge, scaled to 34M PubMed abstracts: 10.7M entities, 30.8M relations + 40 public DBs; probabilistic semantic reasoning runs daily over new abstracts. Key result: LitCoin 1st (NER Jaccard 0.9177, RE 0.6332); BioCreative VIII BioRED 1st (F1 0.5584). No code/data link confirmed; preprint is CC BY-NC-ND — do not copy their data. Use it: design your Maintain loop as daily cutoff-based PubMed batches, not rebuilds (2–3d). Caveat: their scale far exceeds your cluster — ingest Pharos-relevant slices only.

Topic 3 — Link prediction on biomedical KGs

[C1] BioPathNet — Hu, Oleshko, Firmani et al.; Nature Biomedical Engineering, Jan 2026. https://link.springer.com/article/10.1038/s41551-025-01598-z [me]. Path-representation GNN (NBFNet-style): background regulatory graph (BRG) adds message-passing edges without affecting loss; node-type-aware (NTA) negative sampling. Key result: beat TransE/DistMult/RotatE and R-GCN/RAGAT/HGT on gene function, drug repurposing, synthetic lethality, lncRNA; MRR gains 2% (gene function) to 87% (drug repurposing); 23× shorter per-epoch than KR4SL. Code cited (https://github.com/emyyue/BioPathNet) — not opened, UNVERIFIED. Use it: port the two cheap ideas (NTA sampling; BRG-style auxiliary ontology edges for message-passing only) into your PyG loop (3–5d). Caveat: full path model is heavy; repo/license unverified.
[C2] KGOT — Qin, Luo, Tadmor et al.; arXiv 2512.09365, Dec 2025. https://arxiv.org/abs/2512.09365 [sub]. Multimodal KG (>3M relations) + optimal-transport pseudo-labels; includes an ablation of which relation types help link prediction. Key result: TorusE Hits@1 36.3% (molecule–protein only) → 43.7% (+GO) → 47.4% (+protein family) → 53.4% (+KEGG/EC pathways). No code found. Use it: replicate exactly this ablation on your graph with RotatE/ComplEx before committing enrichment budget (1–2d); skip the OT pseudo-labeling. Caveat: molecule–protein task; no code.
[C3] Benchmarking the Impact of Data Leakage on KGE Models for Biomedical Link Prediction — Brière, Stosskopf, Loire et al.; HAL hal-04913469v2 (v3 Sep 2026). https://hal.science/hal-04913469v2 [me]. Tests DL1 (train–test redundancy via near-duplicate/reverse relations), DL2 (node degree as illegitimate feature), DL3 (random vs cold-start vs Orphanet real-world inference set). Key result: DL1 control cut MRR on redundant relations by up to 46%; RESCAL MRR ~0.2 on random splits → 0.016 on the Orphanet inference set. Paper is CC BY-NC 4.0; code repo URL truncated in PDF — UNVERIFIED. Use it: run the DL1 check before any external enrichment (1d). Caveat: preprint; thresholds need retuning.
[C4] PrimeKG-RGCN-LinkPrediction (repo) — arnold117; GitHub, Oct 2025. https://github.com/arnold117/PrimeKG-RGCN-LinkPrediction [me]. End-to-end PyG pipeline (RGCN/GCN/GAT/GraphSAGE/GIN + MLP, DistMult decoder) on a PrimeKG subgraph; hard negatives; undirected-edge-aware split. Key result: v2.0 fixed a real 71.5% reverse-direction leak → 0%; strict eval GAT best (AUC-ROC 0.9866, MRR 0.9031), all GNNs >> MLP. MIT. Use it: copy the split logic into your eval harness — one function guaranteeing no edge/reverse crosses splits (1–2d). Caveat: 1 star, single contributor; author flags residual optimism (embeddings computed over full graph).
[C5] BioGraphBench-PPI — Cabrera-Andrade et al.; Frontiers in Bioinformatics, Oct 2026 (CC BY). https://www.frontiersin.org/journals/bioinformatics/articles/10.3389/fbinf.2026.1966469/full [sub]. Audit-first PPI link-prediction benchmark (STRING v12, BioGRID): fixed 80/10/10 splits, three negative-sampling contracts (random, degree-matched, two-hop), calibration (ECE) reporting. Key result: HGB AUPRC 0.942–0.964 under random negatives, degree-matched cut 0.049–0.259; 2-layer GCN fell to near chance (0.500–0.515) under hard contracts; STRING/BioGRID share 423,528 pairs — direct enrichment-leakage warning. No repo URL stated — UNVERIFIED. Use it: add degree-matched/two-hop contracts + calibration to your internal eval; if you only win under random negatives, the win isn't real (~1d). Caveat: PPI-only.

Risks and common mistakes
Test-edge leakage via enrichment is the #1 risk. Any external KG may contain the held-out Pharos edges. Split-check every enrichment edge against the held-out set before training; dedupe near-duplicate and reverse relations (Brière DL1 cut MRR up to 46%); BioGraphBench found 423,528 shared STRING/BioGRID pairs.
Undirected leakage: no edge or its reverse in more than one split (a published repo's v1 had 71.5% reverse leakage).
Random negatives lie. GNNs at 0.99 AUC under random negatives collapsed to ~0.51 under hard/degree-matched negatives in two independent reports. Evaluate with degree-matched and two-hop negatives; report AUPRC + ECE, not just AUC-ROC.
LLM rationales hallucinate (57% faithfulness) — ground every rationale in retrieved paths plus an LLM-as-judge check.
